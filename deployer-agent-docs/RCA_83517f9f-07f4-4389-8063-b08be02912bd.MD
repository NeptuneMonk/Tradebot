# RCA — micro-stake-trader: frequent 503 "leader pod did not answer in time"

**Deployment:** micro-stake-trader (`d0257e71…`) · active run `83517f9f-07f4-4389-8063-b08be02912bd` · tier_0 · cluster target-2
**DB:** `micro-stake-trader-pump_bot_db` (Emergent-managed Atlas) · frontend_type: cloudflare
**Verdict:** The leader is **periodically dead, restarting, or event-loop-starved**, and separately the relayed handler itself sometimes throws. All three produce the user's 503s. This is a **resource ceiling (tier_0) + external-RPC-storm (app)** problem. It is NOT Mongo and NOT the old uncapped-`ws_events` scan. No pipeline was run; this is read-only RCA.

## Root cause (synthesis)

The follower's 12 s relay times out because the leader is, in rotation, one of: **(a) dead/restarting**, **(b) alive but loop-starved**, or **(c) alive but the relayed handler errors** — all three observed:

1. **Resource — leader keeps dying.** tier_0 caps memory at 512Mi (→ **OOMKilled ×3**) and CPU at 250m (→ event loop starved, `/health` can't answer in nginx's 1 s window → **liveness 503 → kill**). Each death drops the lease and opens a **~39 s leaderless gap** (TTL 30 s + acquire + cold start) in which *every* relayed command 503s. The stale `role=leader` ghost in `pods` confirms uncl ean hand-offs.
2. **App/external amplifier — RPC 429 storm.** Monitor/trade loops hammer the **public** `api.mainnet-beta.solana.com` (and even the quiknode endpoint) and get rate-limited; the retry storm is what starves the loop (15–16 s `last_monitor_tick` lag) and what makes relayed handlers throw `rpc 429` (server.py:3627). This both *causes* the liveness deaths and *directly* fails actions while the leader is up.

Raising `RELAY_TIMEOUT_S` alone only masks case (b) and does nothing for the 39 s leaderless gaps (case a) or the immediate `rpc 429` handler failures (case c).

## Recommended fixes (highest leverage first)

1. **[User] Raise the tier (Resources tab).** tier_0 → tier_1+ to lift the **512Mi / 250m** ceilings. This stops the OOM kills and the CPU-throttle liveness deaths → stops leadership flapping → removes the dominant leaderless-gap 503s. Confirmed by OOMKilled(137) at 512Mi and 15 s loop lag + liveness-503 kills at 250m.
2. **[Code/E1] Kill the Solana RPC 429 storm.** Route all RPC through the paid Helius/QuickNode endpoints with a shared rate-limiter + exponential backoff + short-TTL caching for status/monitor reads; stop falling back to the public `api.mainnet-beta.solana.com`. This is what starves the loop and throws in the relay handler.
3. **[Code/E1] Keep the leader's control plane responsive.** Run RPC/blocking work in a bounded worker so the `pod_commands` poller (0.25 s), lease renew (10 s) and `/health` stay snappy; make lease renewal tolerant of brief loop lag (renew off a dedicated thread, or longer TTL) so a 15 s stall doesn't drop leadership.
4. **[Code/E1] Secondary:** modestly raise `RELAY_TIMEOUT_S` and/or pin the browser's actions+WS to the current leader to cut relay volume — only after 1–3; on its own it just hides the problem.
